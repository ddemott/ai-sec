1. Executive Summary

SecretaryHQ has a strong structural foundation: a clear tab hierarchy, consistent dark-theme design tokens, role-based access control, and excellent keyboard-shortcut coverage. The most critical gaps are concentrated in the first-run experience and the scheduler — two surfaces where new users either abandon or succeed. The setup wizard produces correct data but gives no sense of progress toward "live," leaving first-time owners unsure whether the AI is actually ready to take calls. The scheduler's hour-column grid, while now left-anchored, still uses text-[10px] labels (6.7px at default zoom) that violate WCAG 2.1 AA minimum 12px body-text requirements across 18+ component files. Mobile support is good at 375px for primary flows but the QuickBook panel and scheduler horizontal scroll are the two surfaces most likely to break on iPad in landscape. Overall: fix the 3 P0s and 5 P1s first — together they represent the highest drop-off risk for a new business owner completing onboarding and booking their first appointment.

3. Top 10 Prioritized Improvements

#1 Setup wizard has no "Go Live" readiness signal — owners don't know if the AI is active P0M
dashboard/components/SetupWizard/Step7GoLive.tsx dashboard/components/SetupProgressPill.tsx dashboard/components/DashboardHome.tsx:141

Step 7 ("You're live") closes the wizard but leaves the owner on the Home tab with no visual indicator that the phone number is active and receiving calls. needsSetup only checks services/employees/resources — it never checks whether a phone number is provisioned. A new owner who completes the wizard but hasn't provisioned a number still sees the same dashboard as one whose AI is live. The SetupProgressPill disappears on complete without any "You're live" confirmation. Add a persistent "Phone active" / "Phone not yet active" status card on Home that links to provisioning when offline.

Current — no live status

Proposed — explicit live status

#2 Sub-WCAG text sizes (text-[10px]) used for operational data in 18+ files P0L
dashboard/components/DashboardHome.tsx:426,685,707,716 dashboard/components/scheduler/NewSchedulerView.tsx (hour labels) dashboard/components/ShiftManagementView.tsx:347,472 dashboard/components/ServiceAssignmentView.tsx:390,437

WCAG 2.1 AA requires minimum 12px for body text. text-[10px] resolves to ~10px (6.7px at 67% zoom common on HiDPI laptops). This class appears on customer names, shift times, service labels, and dashboard card metadata — all operationally critical. At 10px, contrast ratios also effectively drop below 3:1 for light-on-dark text. Replace all text-[10px] informational instances with text-xs (12px). Keep 10px only for decorative uppercase trackers where no data depends on it.

Current — 10px fails contrast

Proposed — 12px passes

#3 SetupProgressPill hidden on mobile (md:hidden) — new owners on phones lose onboarding path P0S
dashboard/components/SetupProgressPill.tsx (hidden md:flex) dashboard/components/OutlookLayout.tsx:411 (mobile nav)

The setup progress pill uses hidden md:flex, meaning it is completely invisible on phones (<768px). A new owner signing up on mobile has no affordance to resume the wizard. The mobile bottom nav has no setup entry point either. The fix is a compact icon-only version of the pill for small screens — same link target, just the wand icon + dot-progress — rendered in the mobile bottom nav's overflow or as a floating chip above it.

Current — pill invisible mobile

Proposed — compact chip

#4 QuickBook panel uses bg-white / dark:bg-[#1a1a1a] — breaks on 6 of 8 custom themes P1S
dashboard/components/scheduler/QuickBookPanel.tsx:249 dashboard/components/scheduler/EmployeeDayFocusPanel.tsx:53

The QuickBook slide-over panel and EmployeeDayFocusPanel hardcode bg-white dark:bg-[#1a1a1a] instead of CSS variables. On Forest, Sunset, Nord, Crimson, Discord, or Midnight themes this creates a bright white (or mismatched dark) panel against the theme's custom surface colors. Replace with style={{backgroundColor: 'var(--bg-card)', borderColor: 'var(--border-soft)'}} and the border-gray-200 dark:border-gray-800 classes with border driven by the CSS variable.

Current — hardcoded white

Proposed — CSS var

#5 Login stores role in localStorage but LoginView never stores userRole — ProfileView shows wrong role P1S
dashboard/components/LoginView.tsx:38-45 dashboard/app/register/page.tsx:80 dashboard/lib/SessionContext.tsx (reads userRole)

Register page correctly writes localStorage.setItem('userRole', data.role || 'owner'). LoginView does not write userRole at all — it writes tenantId, userName, userEmail, and authToken but skips role. On next session load, SessionContext reads userRole from localStorage and gets the stale value from the last register call (or undefined). Front-desk users who log in fresh may see owner-level tabs until they log out and back in via register. Fix: add if (data.role) localStorage.setItem('userRole', data.role); to LoginView's success handler.

Current — missing userRole

Fix — add userRole

#6 Scheduler hour slots have no min-height on mobile — touch targets collapse to ~20px P1S
dashboard/components/scheduler/NewSchedulerView.tsx:1105-1160

Each hour slot in the scheduler grid is laid out as a flex row with no explicit min-height. When content is sparse (no appointments), cells shrink to match the empty inner div height, often <24px on mobile — far below the 44px iOS HIG / WCAG 2.5.5 touch target minimum. Users tapping to create a booking hit the wrong hour. Add min-h-[44px] to each hour slot div. The StaffSwimLaneView already uses min-h-[48px] on its slots — the NewSchedulerView should match.

Current — <20px touch targets

Proposed — 44px min

#7 Empty state on Customers tab gives no CTA — users don't know how to add first customer P1S
dashboard/components/CRMView.tsx dashboard/components/ui/EmptyState.tsx

When a tenant has no customers yet, the Customers tab shows an empty list but no instruction or action button pointing toward "Add a customer" or explaining that customers are auto-created when the AI handles calls. New owners on a fresh account will sit confused. Add an EmptyState component with a "Your customers will appear here after your AI handles calls" message plus an "Add customer manually" button that opens the CustomerCreateModal.

Current — bare empty list

Proposed — empty state + CTA

#8 Shift delete button is hover-only (opacity-0 group-hover) — invisible on iPad/touch P1S
dashboard/components/scheduler/StaffSwimLaneView.tsx:417-428

The shift delete button uses opacity-0 group-hover/shift:opacity-100 — it only appears on mouse hover. On iPad and touch screens, there is no hover event, so the button is permanently invisible. Owners editing their schedule on a tablet cannot delete a shift block. Replace with a tap-to-reveal pattern: show the button at reduced opacity always (opacity-40), full on hover/focus, and keep it accessible via keyboard focus.

Current — hover only

Proposed — always visible at 40%

#9 SoloStepReview finalization uses red/yellow/green coverage pills — violates no-grading rule P1S
dashboard/components/SetupWizard/SoloStepReview.tsx dashboard/components/ui/CoverageStatusBadge.tsx

The wizard's final step shows service coverage as green "full" / yellow "partial" / red "uncovered" pills. This is the exact grading-UI pattern documented in CLAUDE.md and prior UX reviews as prohibited (it reads like a score-card). A business that's just starting needs factual readiness info, not performance grades. Replace with neutral factual labels: "Assigned", "Partially assigned", "Not yet assigned" — with no color semantics. Use neutral gray + accent-blue for "configured" vs "needs attention".

Current — graded colors

Proposed — neutral labels

#10 Profile menu shows only "My Profile" and "Business Settings" — no visible path to Help/Docs P2S
dashboard/components/OutlookLayout.tsx:530-565

The profile dropdown contains only "My Profile", "Business Settings", and "Sign Out". There is no link to documentation, help, keyboard shortcuts, or support. New users have no discoverable path to learn the product beyond the first-run tour. Add a "Keyboard shortcuts (?)" item that triggers the ShortcutsHelpModal — it's already wired but only discoverable via the ? key. Optionally add a "Help / Docs" external link.
