SecretaryHQ Dashboard — UX/UI Audit

2026-05-18 · scope: dashboard/ · backend referenced where it surfaces in UI · 27 findings, top-10 recommended

1. Executive summary

The dashboard is structurally solid: a single primary tab bar, clear role-gating, an Outlook-style shell, theme tokens, and a thoughtful Home + Quick Book entry point. The friction is concentrated in three places. (a) Destructive flows are inconsistent — nine sites use window.confirm() / alert() instead of the project's own ConfirmModal primitive, which looks broken in dark themes and bypasses the design system. (b) Touch reachability is incomplete — the appointment delete affordance is a hover-only trash icon, and the mobile bottom nav cram-renders 5+ tabs at 9 px. (c) Status feedback drifts — the "active call" red pulse on the Calls tab refetches only on tab change, so the badge that feels live is actually stale. Fixing the destructive-flow gap alone removes the largest source of perceived-instability and is mostly mechanical.

3. Top 10 prioritized improvements

#1 · Destructive flows still use window.confirm() / alert() P0 M

SchedulerView.tsx:114, 142 · AppointmentView.tsx:382 · EmployeeManagementView.tsx:109, 116 · ServiceAssignmentView.tsx:127 · SkillManagementView.tsx:48, 54 · ResourceManagerView.tsx:114 · scheduler/StaffSwimLaneView.tsx:337 · scheduler/NewSchedulerView.tsx:412 · SkillMatrixView.tsx:107

The CLAUDE.md code-conventions section explicitly mandates ConfirmModal + useConfirm() for destructive actions, and CRMView.tsx, KnowledgeBaseView.tsx, and BusinessSettingsView.tsx already follow that pattern. Nine other destructive callsites still call the browser-native dialog, which (a) renders as a system-styled rectangle that looks broken against the 8 themed dark palettes, (b) cannot be styled, (c) blocks the JS event loop so toast feedback can't run alongside it, and (d) is unkeyboard-trappable in odd ways on mobile Safari. Threading useConfirm() through these sites is mechanical work — the pattern is already proven.

#2 · Hover-only appointment delete is invisible on touch P0 S

scheduler/AppointmentBlock.tsx:213 · scheduler/NewSchedulerView.tsx:1364

Trash icon on every appointment block uses opacity-0 group-hover:opacity-100. On any iPad or phone — and any keyboard user — there's no hover, so the affordance never appears. The popover fallback works, but it requires two taps (tap to open popover, tap Cancel) where a desktop user needs just one (hover, click trash). Replace the hover-reveal with a small always-visible "⋯" overflow menu inside the block (or, for fields wider than 90 px, an always-visible trash at low opacity that brightens on focus/hover).

#3 · "Live" badges aren't live — they refetch only on tab change P0 M

OutlookLayout.tsx:116–133

The animate-pulsing red badge on the Calls tab promises real-time, but the underlying fetch runs in a useEffect whose only dependency is activeTab. A receptionist on Home will never see the badge fire until they navigate. Same shape for the KB unanswered-question badge. Two fixes — both small: (a) poll Api.voice.getActiveCalls() every 5 seconds while the user is authenticated, or (b) subscribe via SSE (backend already streams call events). The pulse animation is fine; the data behind it just needs to actually move.

#4 · Mobile bottom nav crams 5–8 items at 9 px, fails WCAG body-text P1 S

OutlookLayout.tsx:272–317 (text-[9px], h-14, overflow-x-auto)

At 375 px viewport with the admin Globe + 4 primary + 3 advanced tabs the row scrolls horizontally, and the label below the icon renders at 9 px — below the WCAG 2.1 1.4.4 reflow guidance for body text. Drop labels at <360 px and rely on the (already meaningful) icon + active accent color; show labels at ≥360 px with a 12 px minimum. Move the admin Globe into the profile sheet so we never need horizontal scroll on a phone.

#5 · No undo on cancel-appointment P1 S

SchedulerView.tsx:117 · scheduler/NewSchedulerView.tsx

The backend already exposes /appointments/:id/reactivate (added 2026-05-10). The toast on cancel shows "Appointment canceled" but no undo affordance — and the route is wired but invisible from the schedule. Add an Undo button in the success toast (5-second window already exists in the Toast primitive) that calls Api.appointments.reactivate(). This is the single highest-trust UX win for a destructive flow: a misclick is forgivable in ≤5 seconds.

#6 · Drag-to-move on appointment blocks has no discoverable affordance P1 S

scheduler/AppointmentBlock.tsx:186

Outlook-style drag-to-move is wired and works, but the only cue is cursor: move on hover. A new front-desk user will never discover it. Add a 4-dot drag handle on the left edge of every block, plus a small inline tip the first time the user hovers ("Drag to move · click for details").

#7 · Setup wizard / Welcome / Business-type / FirstRunTour overlap risk P1 M

DashboardHome.tsx:185–309 · MyBusinessView.tsx:107–134 · FirstRunTour.tsx

Four overlay layers are gated by independent state flags (welcomePassed, wizardMode, businessTypeReady, wizardDismissed) plus a localStorage tour flag. The code is correct in isolation, but the matrix has at least one ordering where a returning tenant with cleared localStorage opens the tour overlay and the welcome modal simultaneously. Fold all four gates into a single useOnboardingState() reducer that returns exactly one of idle | welcome | chooser | picker | wizard | tour, and assert in tests that only one renders at a time.

#8 · "Start your free trial" link has no signup destination P1 M

LoginView.tsx:144–148

Login footer links to /?trial=true. That route is the marketing landing page; the trial=true param is consumed by DashboardHome on mount but only as a cleanup effect (params.delete('trial')). There is no signup flow — a prospect clicking the link lands back on marketing copy with no obvious next step. Either build a one-page self-serve signup, or rephrase the link as "Contact sales" with a mailto: + Calendly until a signup flow exists. Don't ship the affordance until the destination works.

#9 · Color contrast: --text-muted falls below WCAG AA in 4 of 8 themes P1 S

app/globals.css:48,87,126,164

Navy --text-muted: #3A4E6E on --bg-base: #090E1A measures ~3.8:1 — below WCAG 2.1 AA 4.5:1 for normal-weight body text. --text-muted is used for date subtitles, card descriptions, sub-tab counts (DashboardHome, every Card.description). Same shape in Rose, Forest, Midnight. Bump each --text-muted by ~12 % luminance and run a contrast pass through WebAIM's calculator. A 30-minute fix unlocking AA across the secondary type ramp.

#10 · No keyboard shortcuts at all for a daily-use power surface P1 L

global (none registered)

Front-desk operators are the dashboard's most frequent users by 10×. A receptionist on the phone with a customer wants N to open New Booking, G S to jump to Schedule, / to focus search, Esc to close panels. None exist today. Start small: N for New Booking, / for customer search, G H/G S/G C/G K for the four primary tabs, ? to show a help cheat-sheet. Document in a one-page modal. This is L because the cheat-sheet, the focus-stealing edge cases (modals open, input focused), and the help modal copy take real time — but the value is enormous.
