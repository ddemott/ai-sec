## Discovered during in-session walkthrough

- [ ] **service-duration-15-min · P2 · S — Service duration field should snap to 15-min increments**
  Discovered 2026-05-18 while the user was walking the Solo wizard: the "Duration (minutes)" input is a bare `<Input type="number">` that accepts any integer. The booking grid runs on a 15-minute snap (per CLAUDE.md: "Snap drags to a 15-minute grid to match the booking-form gridding"), so a 22-minute service silently becomes a 30-minute booked slot, leaving 8 wasted minutes per appointment. Three pieces:
  - **Browser nudge:** add `step={15}` and `min={15}` to the `<input type="number">` so the spinner buttons jump in 15s and the browser's own validation surfaces non-multiples.
  - **Helper text:** small line below the input: "Scheduled in 15-minute slots — non-multiples are rounded up on save."
  - **Round-on-save:** wherever the value is sent to the API, `Math.ceil(value / 15) * 15`. Round UP (not nearest) so the staff never feels rushed by a rounded-down booking.
  - **Sites:** `SetupWizard/StepServices.tsx:104` (Solo + Team wizards share this), `ServiceAssignmentView.tsx:318` (edit modal), `ServiceAssignmentView.tsx:451` (new-service wizard), `BusinessSettingsView.tsx` (the new-service form there). Four sites, mechanical.
  - **Optional follow-up:** if the field gets used a lot, replace the raw input with a quick-pick chip group (15 / 30 / 45 / 60 / 90 / Custom). Out of scope for the initial fix.

- [ ] **wizard-vocab-examples · P2 · M — Industry-specific examples in SetupWizard placeholders**
  Discovered 2026-05-18 while the user was walking the Solo wizard: the Service Name input shows `placeholder="e.g. Oil Change, Haircut, Tire Rotation"` — three different industries crammed into one example string. Same shape in StepResources (`"e.g. Bay 1, Chair A, Room 3"`). By the time the wizard reaches these steps, the user has already picked a business type through BusinessTypePicker, so the vocab system knows the industry — the placeholders should adapt.
  - **Backend:** extend each `business_templates` row (or vocabulary endpoint) with `service_examples: string[]` (3 items) and `resource_examples: string[]` (3 items). Migration adds the columns; seed populates per-template.
  - **Frontend:** extend `lib/VocabularyContext.tsx`'s Vocabulary interface + DEFAULTS with the two new arrays; have it consume the new fields from the backend response.
  - **UI:** swap the hardcoded strings in `SetupWizard/StepServices.tsx:96` and `SetupWizard/StepResources.tsx:72` for `\`e.g. ${vocab.service_examples.join(', ')}\``.
  - **Fallback:** when vocab hasn't loaded yet (or for the rare path that bypasses BusinessTypePicker), use a single generic phrase like "e.g. 30-minute consultation" — avoid the cross-industry list that's there today.
  - **Tests:** extend `e2e/vocabulary-overrides.spec.ts` to assert the placeholder text matches the template's examples; add a unit test on StepServices for the fallback case.
