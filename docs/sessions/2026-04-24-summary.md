### 4. Phase 3 — LiveKit agent wired to /agent-tools/* (commit `18caffe`)

Agent worker now drives the full voice flow through the Fastify backend
instead of greeting and idling. Four new modules + rewritten entry point,
all under `agent/src/`:

- **`toolsClient.ts`** — typed fetch wrapper for `/agent-tools/*`. Injects `x-agent-secret` header, surfaces 401/5xx/network/timeout/shape errors as a discriminated `ToolResponse` union (never throws).
- **`sessionContext.ts`** — parses `room.metadata` for `tenant_id`, extracts caller phone + callID from SIP participant attributes, normalizes anonymous-caller markers (`"anonymous"`, `"+1"`, `"unavailable"`, etc.) to `null`.
- **`tools.ts`** — all 10 `llm.tool()` FunctionTools exposed to the LLM. `tenant_id` + `call_id` injected from closure scope — LLM never sees them. Flat LLM args map to the backend's nested `requirements`/`window` body shapes.
- **`prompt.ts`** — builds system instructions with runtime context baked in (tenant name, caller phone, today's date in tenant tz). Includes the OTP turn-order, booking `error_code` translations, no-markdown rules, dynamic anonymous-caller branch.

Entry point (`index.ts`) now: connect → parse metadata → wait 5s for SIP participant → build tools with injected context → build prompt → start `AgentSession` (Deepgram STT + OpenAI LLM/TTS) → greet with `"Thanks for calling DynaTire..."`. Fallback path for misconfigured dispatch rules says something polite instead of silent dead-air.
